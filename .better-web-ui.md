## Design Context

### Users
Working developers inspecting, editing, and running queries against their own databases (local, staging, production). They are SQL-fluent, keyboard-first, and often switching quickly between tables, the query runner, and schema views. The job: find the object, read it, act on it, and see the result without leaving the flow.

### Brand Personality
Precise, quiet, fast. The interface stays out of the way: a technical instrument, not a showcase. Copy is short, neutral, and literal ("Run", "Copy code", "No tables available"); no marketing tone, no exclamation, no explanations users already know.

### Aesthetic Direction
- Dense, utilitarian desktop-tool feel in the DataGrip / TablePlus family.
- Dark and light themes both supported (`.dark` class); zinc neutrals, a single blue primary (`--primary`) used for the active marker and primary actions only.
- JetBrains Mono for all UI text (`--font-sans`), so hierarchy comes from weight, muted color, and spacing, not from font switching.
- Square, edge-to-edge toolbars: `h-8` bars with `border-b`, made of square segments (`h-8! rounded-none border-r border-border`). Inputs and selects are `h-8 rounded-sm`.
- Anti-references: card grids, hero headers, big badges, gradients, helper-paragraph banners, rounded floating panels inside the work area.

### Implementation Defaults
Detected from the existing codebase (takes precedence over any fallback):
- React 19 + Vite, TanStack Router (file routes), TanStack Query, Zustand, nuqs for URL state.
- Tailwind v4 with CSS-variable tokens in `packages/ui/src/styles/tokens.css`.
- shadcn/ui, Radix-flavored (`components.json` style `radix-mira`, baseColor `zinc`), primitives vendored in `packages/ui/src/primitives` and imported as `@db-studio/ui/<name>`. Extra registries: `@kibo-ui`, `@ai-elements`.
- Icons: lucide-react in app code.
- Tables/grids: TanStack Table plus the in-house `packages/ui/src/data-display/data-grid`.
- Editor: Monaco, through the query runner's `CodeEditor`.

### Design Principles
1. **Reuse the screen that already does the job.** A feature that edits or runs SQL renders the query runner, rather than a parallel editor with its own toolbar.
2. **One `h-8` toolbar per concern, segmented, square.** Actions are bordered segments in a top bar; status (duration, rows, type) is muted text on its right. Avoid floating buttons and pill badges for metadata.
3. **Hierarchy through weight and muted color.** Primary text is `text-foreground`, secondary is `text-muted-foreground`, prefixes such as schemas are `text-muted-foreground/60`. Avoid adding size steps or color to rank information.
4. **Sidebars share one list grammar.** Optional schema select (only when there is more than one schema), search with a `/` hint, then dense one-line rows (`pl-4 pr-2 py-1.5 text-sm`) with a `w-1 bg-primary` active marker and a `Kbd` on the right for the row's metadata.
5. **Say less.** Empty and error states are one short line; no instructional paragraphs above work areas.
